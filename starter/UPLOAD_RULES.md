# Правила загрузки web-демоверсии

Автор загружает на платформу web-сборку Godot одним zip-архивом. Платформа проверяет архив по правилам ниже и либо принимает его, либо отклоняет с кодом причины. Эталонная реализация проверки — `tools/validate_build.py`.

## Правила

Правила проверяются по порядку. Если нарушено несколько правил, причиной отказа считается первое нарушенное.

| № | Правило | Код причины |
|---|---|---|
| 1 | Размер zip-файла — не больше 200 МБ (209 715 200 байт включительно). | `archive_too_large` |
| 2 | Файл — корректный zip-архив, оглавление читается. | `not_zip` |
| 3 | Все пути внутри архива безопасны: не абсолютные (`/…`, `C:\…`), без компонентов `..`, без обратных слешей. Такой архив нельзя распаковать за пределы папки демоверсии. | `unsafe_path` |
| 4 | Сумма **распакованных** размеров файлов — не больше 500 МБ (524 288 000 байт). Так платформа защищается от zip-бомб. | `unpacked_too_large` |
| 5 | В корне сборки есть `index.html`. | `missing_index` |
| 6 | В корне сборки есть хотя бы один файл `.wasm`. | `missing_wasm` |
| 7 | В корне сборки есть хотя бы один файл `.pck`. | `missing_pck` |

## Уточнения

- **Корень сборки** — корень архива. Если все файлы архива лежат в одной папке верхнего уровня (так получается, когда архивируют саму папку экспорта), корнем сборки считается эта папка.
- Расширения файлов сравниваются без учёта регистра: `GAME.PCK` — это файл `.pck`.
- Служебные файлы архиваторов не учитываются ни в одном правиле: папка `__MACOSX/`, файлы `.DS_Store` и `Thumbs.db`.
- Папки внутри архива (записи с `/` на конце) файлами не считаются.
- Пустой архив, в котором нет ни одного файла, отклоняется с кодом `missing_index`.

## Вывод валидатора

```
python3 tools/validate_build.py --csv results.csv archives/*.zip
```

В консоль печатается строка на каждый архив: `имя<TAB>accept` или `имя<TAB>reject<TAB>код<TAB>пояснение`. В `results.csv` — колонки `archive`, `verdict` (`accept` / `reject`), `reason` (код причины, для принятых — пусто).
